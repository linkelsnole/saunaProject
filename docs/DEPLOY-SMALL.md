# Обновление малой сауны: webpanel-s

Команда предназначена только для существующего сервиса `webpanel-s` на сервере бань `212.164.86.237`. Она не меняет команду запуска службы, порт сервера данных и имя PLC, не заменяет файл базы пользователей. При первом запуске этой версии приложение однократно меняет пароли admin/user и отзывает их прежние сессии; читатель не меняется. Путь к JAR читается из конфигурации службы; пути старого deploy.sh не используются.

## Проверить доступ

```sh
python3 /Users/dmitry/Documents/saunaProject/deploy-small.py --check
```

## Загрузить готовый проверенный JAR

```sh
python3 /Users/dmitry/Documents/saunaProject/deploy-small.py --deploy
```

Если администратор предусмотрел команды `service webpanel-s stop/start` без sudo:

```sh
python3 /Users/dmitry/Documents/saunaProject/deploy-small.py --deploy --no-sudo
```

Этот режим использует только `service webpanel-s stop/start`, в том числе при возврате предыдущего JAR. Автоматического перехода на sudo нет. При отказе в остановке рабочий JAR не заменяется. Режим несовместим с `--ask-sudo`.

Если сервер требует пароль sudo:

```sh
python3 /Users/dmitry/Documents/saunaProject/deploy-small.py --deploy --ask-sudo
```

Запускайте из обычного терминала Mac. Пароль пользователя `webpanel` на сервере вводится прямо в SSH-терминале, символы не отображаются. Это не пароль веб-интерфейса или Mac. Пароль не сохраняется скриптом. До остановки проверяются разрешения sudo на обе команды stop/start; если их нет, обратитесь к администратору сервера. В этом режиме требование беспарольного sudo ниже не применяется.

Чтобы сначала заново собрать текущий код с тестами, добавить `--build`.

При другом SSH-порте добавить `--ssh-port НОМЕР`. Для проверки веб-интерфейса используется 8082; при другом порте службы добавить `--web-port НОМЕР`. Эти параметры не изменяют настройки сервиса.

Нужны доступ по SSH с ключом `~/.ssh/deploy_key`, уже известный ключ сервера в known_hosts, Python 3 на Mac и сервере, права владельца JAR и разрешённые без пароля команды `sudo service webpanel-s stop/start`. При отсутствии доступа команда завершается до остановки сервиса.

## Последовательность

1. Проверяет SSH и существующий сервис.
2. Проверяет локальный архив и загружает его во временный каталог.
3. Проверяет SHA-256 на сервере и сохраняет предыдущий JAR рядом с рабочим.
4. Блокирует одновременное обновление этой службы.
5. Останавливает только `webpanel-s`, атомарно заменяет JAR, запускает тот же сервис с прежними параметрами.
6. Проверяет активный процесс и точное совпадение главной страницы с установленным JAR три раза подряд.
7. При неудаче установки/проверки запуска возвращает прежний JAR и запускает его, если он работал до обновления.

Проверка главной страницы подтверждает запуск веб-приложения, а не доступность всех регистров PLC. Базу данных команда не заменяет и не откатывает; для будущих несовместимых миграций БД нужен отдельный план. При обрыве SSH после начала установки результат может быть неизвестен: проверить `sudo service webpanel-s status` и контрольную сумму JAR до повторного запуска.

## Смена паролей admin/user в текущей сборке

При первом запуске JAR пароли двух стандартных аккаунтов заменяются в существующей базе. Повторный запуск не сбрасывает их заново. Старые refresh-сессии этих аккаунтов удаляются; access-токены предыдущей версии для них больше не принимаются. Читатель и остальные аккаунты этой миграцией не изменяются. Пароли переданы отдельно; исходники и JAR содержат только BCrypt-хеш.

Если установщик откатится к прежнему JAR, его прежний код инициализации может снова выставить старые пароли. Смена паролей считается действующей только при успешном запуске новой версии. При повторной установке новая версия распознаёт восстановленные старым JAR пароли и заменяет их снова; самостоятельно назначенные новые пароли сохраняются.
